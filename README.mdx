ClawPanel is a visual management panel for multiple AI Agent frameworks. It currently supports [OpenClaw](https://github.com/1186258278/OpenClawChineseTranslation), [Hermes Agent](https://github.com/nousresearch/hermes-agent), [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness), [OpenCode](https://github.com/anomalyco/opencode), and experimental [Pi](https://github.com/earendil-works/pi). Its **built-in AI assistant** helps install components, diagnose configuration, investigate problems, and fix errors. Eight tools, four operating modes, and interactive Q&A make agent management accessible to both new and experienced users.

> 🌐 **Website:** [claw.qt.cool](https://claw.qt.cool/) | 📦 **Downloads:** [Download center](https://claw.qt.cool/download) | 📚 **Documentation:** [Documentation index](docs/index.md) | **GitHub Releases:** [Latest release](https://github.com/qingchencloud/clawpanel/releases/latest) | **China mirror:** [AtomGit](https://atomgit.com/qingchencloud/clawpanel)

## 🧪 DeepSeek Harness: configure and work inside ClawPanel

- **Managed runtime** — Install, start, stop, and uninstall a pinned, validated version from Runtime & Configuration without changing the global npm environment. Stable defaults to 0.2.0-rc.2. You can explicitly install the 0.2.1-alpha.2 candidate and switch back to stable at any time.
- **Dedicated workspace** — Open the complete DSH Web interface from Workspace to chat, select workspaces, switch models, and manage sessions.
- **Unified model channels** — Synchronize providers, API keys, context windows, output limits, and default models from ClawPanel to DSH, then read back the settings to verify them.
- **Secure Web/headless embedding** — DSH listens on loopback. Remote Web deployments use short-lived tokens and a sandbox proxy to access the full interface without exposing another public port.

## 🔥 Development boards and embedded devices

ClawPanel provides a **pure Web deployment mode** with no GUI dependency, making it suitable for ARM64 development boards and embedded devices.

- **Orange Pi / Raspberry Pi / RK3588** and other ARM64 boards — run with npm run serve.
- **Docker ARM64** — Build locally with the repository Dockerfile. See the [ARM deployment guide](docs/armbian-deploy.md).
- **Armbian / Debian / Ubuntu Server** — The one-click deployment script detects the architecture automatically.
- Rust, Tauri, and a graphical desktop are not required for Web mode. The basic Web backend requires **Node.js 18+**. Node.js 24.16.0+ (24.x) is recommended for full engine deployment. OpenClaw Gateway compatibility is checked against the installed version's engines.node requirement.

> 📖 See the [Armbian deployment guide](docs/armbian-deploy.md) and [Web development instructions](#web-development-without-rusttauri).

## Download and install

Visit the [official download center](https://claw.qt.cool/download) for the latest version. The page detects your operating system automatically, or you can choose a Windows, macOS, or Linux package manually. [GitHub Releases](https://github.com/qingchencloud/clawpanel/releases/latest) is also available.

### macOS

| Chip | Package | Description |
|---|---|---|
| Apple Silicon (M1/M2/M3/M4) | ClawPanel_x.x.x_aarch64.dmg | Macs released from late 2020 onward |
| Intel | ClawPanel_x.x.x_x64.dmg | Intel-based Macs |

To identify your chip, open the Apple menu → **About This Mac** and check the Chip field.

Open the .dmg file, **drag ClawPanel into the Applications folder first**, and then launch it.

> **⚠️ macOS says the app is damaged or cannot verify the developer?** The app is unsigned, so macOS may block it. Run this command in Terminal:
>
> ~~~bash
> sudo xattr -rd com.apple.quarantine /Applications/ClawPanel.app
> ~~~
>
> Alternatively, open **System Settings → Privacy & Security**, find ClawPanel, and select **Open Anyway**.
>
> If you see No such file, move the app into Applications first, or use:
>
> ~~~bash
> sudo xattr -rd com.apple.quarantine ~/Downloads/ClawPanel.app
> ~~~

### Windows

| Format | Package | Description |
|---|---|---|
| EXE installer | ClawPanel_x.x.x_x64-setup.exe | Recommended; double-click to install |
| MSI installer | ClawPanel_x.x.x_x64_en-US.msi | Enterprise deployment / silent installation |

### Linux

| Format | Package | Description |
|---|---|---|
| AppImage | ClawPanel_x.x.x_amd64.AppImage | No installation; run chmod +x and launch |
| DEB | ClawPanel_x.x.x_amd64.deb | Debian / Ubuntu: sudo dpkg -i *.deb |
| RPM | ClawPanel-x.x.x-1.x86_64.rpm | Fedora / RHEL: sudo rpm -i *.rpm |

### Linux server (Web version)

No desktop environment? Deploy the ClawPanel Web version with one command and manage multiple engines through a browser:

~~~bash
curl -fsSL https://raw.githubusercontent.com/qingchencloud/clawpanel/main/scripts/linux-deploy.sh | bash
~~~

A fresh deployment uses the official stable OpenClaw release by default. To explicitly use the Chinese-localized build:

~~~bash
curl -fsSL https://raw.githubusercontent.com/qingchencloud/clawpanel/main/scripts/linux-deploy.sh | OPENCLAW_SOURCE=chinese bash
~~~

After deployment, open http://SERVER_IP:1420 and select an engine from the left navigation. Model testing, working directories, and engine processes run on the server. Engine capabilities may differ.

You can also download the complete Web server package, web-x.y.z.zip, from GitHub Releases. For upgrades, replace the frontend and Node.js backend together and restart the service. frontend-hot-update-x.y.z.zip is only for desktop hot updates and must not be used for Web server deployments.

📖 See the [Linux deployment guide](docs/linux-deploy.md).

### Docker deployment

~~~bash
docker run -d --name clawpanel --restart unless-stopped \
  -p 1420:1420 -v clawpanel-data:/root/.openclaw \
  node:24.16.0-slim \
  sh -c "apt-get update && apt-get install -y git && \
    npm install -g openclaw@2026.10.4 --registry https://registry.npmmirror.com && \
    git clone https://github.com/qingchencloud/clawpanel.git /app && \
    cd /app && npm ci && npm run build && npm run serve"
~~~

📖 See the [Docker deployment guide](docs/docker-deploy.md) for Compose, custom images, Nginx reverse proxy, and more.

## Upgrade ClawPanel

Choose the upgrade procedure that matches your installation.

### macOS / Windows desktop app

The desktop app checks for new versions through the official website API. When an update is available:

1. Open ClawPanel; an update notification appears when a new version is available.
2. Select **Download recommended installer**. Your browser downloads the package from the official mirror.
3. Quit ClawPanel and install the package over the existing version.
4. You can also check for updates manually from the **About** page.

> **Manual upgrade:** If the official download fails, get the latest installer from [GitHub Releases](https://github.com/qingchencloud/clawpanel/releases/latest) and install it over the existing version. Your data will be preserved.

### Linux desktop app

| Format | Upgrade |
|---|---|
| AppImage | Download the latest .AppImage, replace the old file, run chmod +x, and launch |
| DEB | sudo dpkg -i ClawPanel_latest_amd64.deb |
| RPM | sudo rpm -U ClawPanel-latest-1.x86_64.rpm |

### Linux Web version

**Option 1: One-command upgrade (recommended)**

System-wide installation (/opt/clawpanel):

~~~bash
curl -fsSL https://raw.githubusercontent.com/qingchencloud/clawpanel/main/scripts/linux-deploy.sh | sudo bash
~~~

Per-user installation (~/.local/share/clawpanel):

~~~bash
curl -fsSL https://raw.githubusercontent.com/qingchencloud/clawpanel/main/scripts/linux-deploy.sh | bash
~~~

The script reads the working directory from the existing systemd service, runs git pull --ff-only, rebuilds the application, and restarts the service. It stops with a clear error if Git fails, uncommitted local changes exist, or permissions do not match. It will not build from stale source.

**Option 2: Manual upgrade**

~~~bash
cd /opt/clawpanel  # Replace with your installation directory
git status --short  # Resolve local changes first if this prints anything
git pull --ff-only origin main
npm ci
npm run build
node -p "require('./package.json').version"  # Should print the latest version
sudo systemctl restart clawpanel
~~~

For a per-user service, replace the last command with systemctl --user restart clawpanel. If the browser still shows the old version, force-refresh with Ctrl+F5.

> **Important:** Do not upgrade the Web version by replacing only dist/. The frontend, scripts/dev-api.js, and WebSocket proxy must all come from the same release. New versions check frontend/backend compatibility at /__api/health; a mismatch stops loading and prompts you to install the complete Web package.

> **Upgrade OpenClaw:** ClawPanel and OpenClaw versions must be compatible. Upgrade OpenClaw from Service Management, or run:
>
> ~~~bash
> sudo npm install -g openclaw@2026.10.4 --registry https://registry.npmmirror.com
> ~~~
>
> The localized build can be installed explicitly with:
> sudo npm install -g @qingchencloud/openclaw-zh@2026.7.1-2-zh.1 --registry https://registry.npmmirror.com

### Docker upgrade

**Docker Compose (recommended)**

~~~bash
cd /path/to/clawpanel  # Directory containing docker-compose.yml
docker compose build --no-cache clawpanel
docker compose up -d clawpanel
~~~

**Using docker run**

~~~bash
# Stop and remove the old container; data in the Volume is preserved
docker stop clawpanel
docker rm clawpanel

# Start the new container
docker run -d --name clawpanel --restart unless-stopped \
  -p 1420:1420 -v clawpanel-data:/root/.openclaw \
  node:24.16.0-slim \
  sh -c "apt-get update && apt-get install -y git && \
    npm install -g openclaw@2026.10.4 --registry https://registry.npmmirror.com && \
    git clone https://github.com/qingchencloud/clawpanel.git /app && \
    cd /app && npm ci && npm run build && npm run serve"
~~~

**Upgrade only OpenClaw inside the container**

~~~bash
docker exec -it clawpanel npm install -g openclaw@2026.10.4 --registry https://registry.npmmirror.com
~~~

### macOS / Windows Web version

For a Web deployment from source (not the desktop app), use the same procedure as Linux:

~~~bash
cd clawpanel  # Replace with your installation directory
git pull origin main
npm install
npm run build
npm run serve  # Restart the service
~~~

## Uninstall ClawPanel

### macOS desktop app

~~~bash
sudo rm -rf /Applications/ClawPanel.app
# Optional: remove application data and configuration
rm -rf ~/Library/Application\ Support/com.clawpanel.app
rm -rf ~/Library/Caches/com.clawpanel.app
rm -rf ~/Library/Preferences/com.clawpanel.app.plist
~~~

### Windows desktop app

Use **Settings → Apps → Installed apps**, search for ClawPanel, and select **Uninstall**. Alternatively, use **Control Panel → Programs → Uninstall a program**.

Optionally remove leftover data:

~~~powershell
Remove-Item -Recurse -Force "$env:APPDATA\com.clawpanel.app"
Remove-Item -Recurse -Force "$env:LOCALAPPDATA\com.clawpanel.app"
~~~

### Linux desktop app

| Format | Uninstall |
|---|---|
| AppImage | Delete the .AppImage file |
| DEB | sudo dpkg -r clawpanel |
| RPM | sudo rpm -e ClawPanel |

Optionally remove application data:

~~~bash
rm -rf ~/.local/share/com.clawpanel.app
rm -rf ~/.config/com.clawpanel.app
~~~

### Linux Web version

~~~bash
sudo systemctl stop clawpanel
sudo systemctl disable clawpanel
sudo rm -f /etc/systemd/system/clawpanel.service
sudo systemctl daemon-reload
sudo rm -rf /opt/clawpanel
# Optional: uninstall OpenClaw
sudo npm uninstall -g @qingchencloud/openclaw-zh
# Optional: delete OpenClaw data, configuration, API keys, and Agent memory
rm -rf ~/.openclaw
~~~

> ⚠️ The final command deletes all OpenClaw configuration, including API keys, model settings, and Agent memory. Confirm that you no longer need this data before running it.

### Docker

~~~bash
docker stop clawpanel
docker rm clawpanel
# Optional: remove the image
docker rmi $(docker images --filter "reference=*clawpanel*" -q) 2>/dev/null
# Optional: remove the data volume (deletes configuration)
docker volume rm clawpanel-data
~~~

For Docker Compose:

~~~bash
cd /path/to/clawpanel
docker compose down          # Stop and remove containers
docker compose down -v       # Also remove volumes (use with care!)
docker rmi $(docker images --filter "reference=*clawpanel*" -q) 2>/dev/null
~~~

## 🤖 AI assistant highlights

The built-in AI assistant is more than a chatbot: it can **interact directly with your system** to diagnose and repair problems and help prepare pull requests.

### Four operating modes

The interface color changes with the selected mode to make the current permission level visible.

| Mode | Icon | Tools | File writes | Confirmation | Use case |
|---|---|---|---|---|---|
| **Chat** | 💬 | No | No | — | Q&A only; does not interact with the system |
| **Plan** | 📋 | Yes | No | Yes | Read configuration and logs and propose a plan without changing files |
| **Execute** | ⚡ | Yes | Yes | Yes | Normal work; risky operations require confirmation |
| **Unrestricted** | ∞ | Yes | Yes | No | Automatic operation without tool-call confirmation dialogs |

Settings also provide independent **Terminal** and **Files** tool toggles. These take priority over the selected mode: if Terminal is disabled, commands cannot run even in Unrestricted mode.

### Eight built-in tools

| Tool | Purpose | Example |
|---|---|---|
| ask_user | Ask a single-choice, multiple-choice, or free-text question | Which repository should receive this change? |
| get_system_info | Retrieve OS, architecture, and home directory | Choose PowerShell or Bash |
| run_command | Execute shell commands | Restart Gateway or inspect logs |
| read_file | Read a file | Inspect openclaw.json |
| write_file | Write a file | Fix configuration or generate a script |
| list_directory | Browse a directory | List .openclaw contents |
| list_processes | Inspect running processes | Check whether Gateway is running |
| check_port | Check whether a port is occupied | Identify the process using port 18789 |

### Interactive Q&A (ask_user)

The assistant can request information in three ways:

- **Single choice** — Choose one option, with the ability to enter a custom answer.
- **Multiple choice** — Select several items, such as components to inspect.
- **Free text** — Describe an issue or provide other information.

The assistant waits for your response before continuing, enabling human–AI collaboration.

### Pull Request assistant and bug reports

1. 🐛 **Prepare a bug report** — Collect system information, inspect error logs, and format findings as a GitHub Issue. You can review and submit the report.

## Quick start

### 1. Initial setup

On first launch, ClawPanel opens the **Initial Setup** page and guides you through environment checks:

- ✅ **Node.js** — Detected automatically; one-click installation is offered if missing.
- ✅ **Git** — Detected automatically and configured for HTTPS mode to avoid SSH connectivity problems.
- ✅ **Engine runtime** — Select OpenClaw, Hermes, DSH, OpenCode, or Pi from the left navigation and follow that engine's setup page.

> Completed steps receive a green check. When all checks pass, select **Go to Model Configuration**.

### 2. Configure an AI model

Open **General → Model Channels** and add at least one provider. After saving, explicitly synchronize the configuration to the target engine.

| Provider | Get an API key |
|---|---|
| DeepSeek | [platform.deepseek.com](https://platform.deepseek.com/) |
| MiniMax | [platform.minimaxi.com](https://platform.minimaxi.com/) |
| OpenAI | [platform.openai.com](https://platform.openai.com/) |

| Ollama (local) | Free; no key required; detected after installation |

Enter the Base URL and API Key, select **Test Connection**, and then save.

### 3. Start the runtime

For OpenClaw, open **Service Management** and select **Start** to launch Gateway. DSH, OpenCode, and Pi are started and stopped independently from each engine's **Runtime & Configuration** page.

> Gateway is OpenClaw's core service. Other engines have their own local runtimes and do not share Gateway's lifecycle.

### 4. Start chatting

Open OpenClaw's **Live Chat**, or open another engine's **Workspace**. Select a model and send a test message. Sessions, projects, and permissions are independent for each engine.

## Web deployment guide

The Web version is intended for Linux servers without a desktop environment. It lets you manage multiple engines remotely. Model tests, working directories, and engine processes run on the ClawPanel server.

### Requirements

- **Node.js:** 24.16.0+ (24.x) recommended. ClawPanel checks compatibility against the installed OpenClaw engines.node requirement. Official stable version 2026.10.4 requires >=24.16.0 <25 or >=26.1.0.
- **Git:** Required for OpenClaw dependency installation.
- **Ports:** 1420 (ClawPanel) and 18789 (Gateway).

### One-command deployment

~~~bash
curl -fsSL https://raw.githubusercontent.com/qingchencloud/clawpanel/main/scripts/linux-deploy.sh | bash
~~~

After deployment, open http://SERVER_IP:1420.

### Security considerations

> ⚠️ **Public exposure risk:** The Web version listens on all network interfaces by default.

1. **Set an access password** — Change the default password on first login or configure one in Security Settings.
2. **Restrict access with a firewall** — Allow port 1420 only from trusted IP addresses.
3. **Use Nginx with HTTPS** — Strongly recommended for production.

<details><summary><strong>Nginx reverse proxy example</strong></summary>

~~~nginx
server {
    listen 443 ssl;
    server_name openclaw.example.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://127.0.0.1:1420;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # WebSocket support (required for live chat)
    location /ws {
        proxy_pass http://127.0.0.1:18789;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }
}
~~~

</details>

### API key security

- API keys are stored on the server in ~/.openclaw/openclaw.json and are not transmitted externally by ClawPanel.
- Restrict permissions on ~/.openclaw/ (for example, chmod 700).
- If multiple people use the service, each person should use a separate OpenClaw instance.

## FAQ

### macOS says the app is damaged and cannot be opened

The app is not signed with an Apple Developer certificate, so Gatekeeper may block it. Run:

~~~bash
sudo xattr -rd com.apple.quarantine /Applications/ClawPanel.app
~~~

Or open **System Settings → Privacy & Security** and select **Open Anyway**.

### macOS cannot detect Node.js

When launched from Finder or the Dock, ClawPanel's PATH may not include the Node.js installation directory.

**Fixed in v0.4.1:** Common paths such as /usr/local/bin, /opt/homebrew/bin, ~/.nvm, and ~/.volta are added automatically.

As a temporary workaround, launch from Terminal:

~~~bash
open /Applications/ClawPanel.app
~~~

### Windows OpenClaw installation fails with ENOENT (-4058)

This is usually caused by file permissions or the npm cache:

1. Run ClawPanel as Administrator.
2. Or open PowerShell as Administrator and install manually:
   ~~~powershell
   npm install -g openclaw@2026.10.4 --registry https://registry.npmmirror.com
   ~~~
3. If it persists, clear the npm cache: npm cache clean --force.

### Windows installation fails with exit code 128 (access rights)

Git is required for npm dependencies. If Git is installed but error 128 persists, a dependency may be cloning over SSH without a configured GitHub SSH key. Configure Git to use HTTPS:

~~~powershell
git config --global url."https://github.com/".insteadOf ssh://git@github.com/
git config --global url."https://github.com/".insteadOf git@github.com:
~~~

If Git is not installed, install [Git for Windows](https://git-scm.com/download/win). **v0.4.2 and later configure HTTPS mode automatically.**

### Windows installation fails with EPERM (operation not permitted)

A file may be locked by another process. Close ClawPanel and all Node.js processes, open PowerShell as Administrator, and reinstall:

~~~powershell
npm cache clean --force
npm install -g openclaw@2026.10.4 --registry https://registry.npmmirror.com
~~~

### Node.js is not detected after installation (Windows)

Select **Detect Again** after installing Node.js. If the old version is still displayed, restart ClawPanel or check PATH precedence.

For a non-default installation directory (such as D:\nodejs or F:\AI\Node), use **Auto Scan** in the setup wizard or enter the directory manually. ClawPanel validates the Node.js version against the current OpenClaw requirements and will not save an incompatible path.

### Gateway fails to start

| Symptom | Cause | Solution |
|---|---|---|
| Port 18789 is occupied | A previous Gateway process remains | Run pkill -f openclaw, then restart |
| Configuration is damaged | Invalid openclaw.json format | Open Service Management → Restore from Backup |
| Repeated crashes | Invalid API key or model configuration | Run AI assistant's One-click troubleshooting |
| "auth mode" error | Incompatible authentication settings | Reset Gateway authentication in Security Settings |

If the problem persists, inspect Gateway logs in the **Log Viewer**.

### Model connection times out or tests fail

1. **Check the API key** — Ensure it has not expired and the account has sufficient balance.
2. **Check the Base URL** — Providers use different formats. Avoid an extra trailing /v1; ClawPanel handles it automatically.
3. **Check network access** — Accessing OpenAI from mainland China may require a proxy. DeepSeek, Alibaba Cloud Model Studio, and Ollama can generally be accessed directly within China.
4. **Ollama special case** — Use http://127.0.0.1:11434 without /v1; ClawPanel adds the required path automatically.

### WebSocket disconnects or chat does not respond

1. Make sure Gateway is running (the top status indicator should be green).
2. Enable WebSocket support in the reverse proxy (see the Nginx example).
3. With HTTPS, WebSocket connections use wss://. This is handled automatically in v0.7.3 and later.
4. Clear the browser cache and reload.

### The Web version reports "Command not implemented"

Upgrade to **v0.8.5 or later**. Older Web backends lacked some command handlers; v0.8.5 completed them.

~~~bash
cd /opt/clawpanel  # Replace with your installation directory
git pull origin main
npm install
npm run build
sudo systemctl restart clawpanel  # Or: pm2 restart clawpanel
~~~

### Messaging channel changes do not take effect after saving

1. Make sure Gateway is running.
2. Feishu / DingTalk: publish the application version on the relevant developer platform.
3. Feishu: for direct-message testing, find the bot in Workbench. For group chats, add it through Group Settings → Smart Group Assistant.
4. DingTalk: the receiving mode must be **Stream mode**.

### Remove old frontend hot-update files / return to the bundled frontend

Recent ClawPanel versions use complete installer packages for updates. The frontend hot-update directory is retained for compatibility with older resources and rollback. If you used the old hot-update feature, files are stored here:

| OS | Path |
|---|---|
| Windows | %USERPROFILE%\.openclaw\clawpanel\web-update\ |
| macOS / Linux | ~/.openclaw/clawpanel/web-update/ |

If the interface looks incorrect or you want to return to the bundled frontend, delete the directory and restart:

~~~bash
# macOS / Linux
rm -rf ~/.openclaw/clawpanel/web-update

# Windows PowerShell
Remove-Item -Recurse -Force "$env:USERPROFILE\.openclaw\clawpanel\web-update"
~~~

After restarting, ClawPanel automatically uses the bundled frontend.
